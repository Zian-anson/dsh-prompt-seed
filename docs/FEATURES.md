## 模块 1 · 输入框按钮（唯一的用户界面）

入口：`conversation.input.right` 槽位，模型选择器左侧。插件只注册这一个槽位。

| 功能 | 触发 | 输入 → 输出 | 状态 |
|---|---|---|---|
| **星标常驻** | 自动 | 草稿空 → 半透明常驻；有内容 → 呼吸微光 | ✅ 渲染测试 |
| **五状态机** | 自动 | idle ✦ / busy ⟳ / revert ↺ / declined 🛡（中性色）/ error ⚠（红色） | ✅ 渲染测试 |
| **发起优化** | 左键点星标 | 草稿 → 改写稿写回输入框 | ✅ 线上实测 |
| **取消** | busy 态再点 | 丢弃响应，草稿不动 | ⚠️ **仅前端丢弃**，宿主模型调用仍在跑并计费 |
| **恢复原文** | revert 态点 ↺ | 写回原文 | ✅ 单测 + 线上（按钮可见） |
| **闸门凭证** | revert 态悬停 | `保真 ✓ · 增加 150 字 · 补全：边界情况、失败处理` | ✅ 单测（解析+回传）；`⟳`=收敛过 |
| **字符增减徽标** | revert 态 | 按钮上显示 `✓ +150` | ✅ 渲染测试 |
| **再来一版** | revert 态点 ✦ | 拿**原文**重新补全，追加为历史新版本 | ⚠️ **从未在真实浏览器点击过**，仅渲染/产物核查 |
| **回到上一版** | revert 态且有 ≥2 版时点 ‹ | 弹掉当前版本，写回上一版 | ⚠️ 同上 |
| **查看被拒版本** | declined 态点 👁 | 把闸门拒绝的稿子写进输入框（可撤销） | ⚠️ 同上 |
| **切换深度档位** | **右键**点星标 | 循环 `自动 → 轻 → 标准 → 深度`，记忆在 localStorage | ✅ 产物核查；**入口最隐蔽** |
| **引用降级提示** | 草稿含 @/命令芯片时悬停 | 明说"引用会变成纯文本" | ✅ 单测 |
| **引用守恒校验** | 写回前自动 | 任一芯片标签丢失 → 拒绝写回，保留原文 | ✅ 单测 |
| **过期响应丢弃** | 自动 | 请求期间草稿被改动 → 丢弃结果（draftRev CAS） | ✅ 单测 |
| **隐式反馈** | 自动 | applied / reverted / retried / submitted，30 秒窗口 | ✅ 线上（样本里有 applied/submitted/reverted） |

## 模块 3 · 改写流水线（插件本体）

| 功能 | 输入 → 输出 | 状态 |
|---|---|---|
| **补全式改写** | 种子草稿 → 具体可执行请求（实测 11–22×） | ✅ 线上实测 |
| **精确模式** | 已完整指令 → 近原样润色（实测 1.0–1.1×） | ✅ 线上实测 |
| **补全闸重试** | 第一稿实质未变且输入开放式 → 温度 0.4→0.7 重试，最多 2 次 | ✅ 单测 |
| **语义审判** | 原文+改写 → `OK` 或五类越线（DISTORTED/SCOPE_ADDED/CONTRADICTED/TONE_SHIFTED/PADDED）+ THIN | ✅ 线上（gate 字段） |
| **精确短路** | 精确 ∧ 实质未变 ∧ 锚定词守恒 → 跳过审判（1.7s→0.9s） | ✅ 线上（`gate=unverified`） |
| **锚定词守恒** | 标识符/路径/数字一个不少才允许短路 | ✅ 单测（`dayjs→moment` 回归守卫） |
| **定向修复 + 无条件复核** | 越线 → 只摘越线处 → **重新审判** → 仍越线则拒绝 | ✅ 单测；线上已出现 `rechecked=true` |
| **保守兜底** | 修不动时给"轻润色、不新增"稿，而不是赌第二次拒绝 | ✅ 单测（契约内容） |
| **THIN 分支** | 审判说太薄 → 再补一次 → 仍失真则回退薄稿（`tier=thin`） | ✅ 单测 |
| **拒绝路径** | 复核仍越线 → `fidelity_rejected` + 中文类别 + 被拒稿（**不带 text**） | ✅ 脚本化实测 |
| **fail-open** | 审判调用失败/无法解析 → 接受改写 | ✅ 脚本化实测 |
| **结果清洗** | 剥围栏、首尾引号、模型自加前缀 | ✅ 单测 |
| **截断识别** | `finish=max-tokens` → `truncated`，**截断稿不回填** | ✅ 脚本化实测 |

调用次数：短路 1 次 · 顺利 2 次 · 修复 4 次。实测 0.9s（短路）～20s（最差）。

## 模块 4 · 深度档位

| 功能 | 入口 | 状态 |
|---|---|---|
| **四档循环** | 右键星标：`自动 / 轻 / 标准 / 深度` | ✅ |
| **标准档 = 基线** | 不加任何 prompt 后缀（与引入档位前逐字节相同） | ✅ 单测 + 逐字节 diff |
| **轻/深度档** | 加对应后缀，仅这两档偏离基线 | ✅ 单测 |
| **非法值降级** | 未知 depth → 标准档（旧客户端兼容） | ✅ 单测 |
| **自适应** | 本地统计 `reverted`/`retried` 决定 auto 档，需 2 个信号才动 | ⚠️ 逻辑单测覆盖，**从未在真实数据上触发**（样本量不足） |

**⚠️ 实测发现**：每档 5 次取中位，`light` 133 / `standard` 143 / `deep` 145（另一输入 134/139/176）。
**轻与标准的差距（10–15 字）小于档内波动（34–70 字）——两档实际不可分辨，只有 deep 稳定更深。**
建议砍掉 light 只留三档（未实施，待决策）。

## 模块 11 · 信号推断与短指令度契约（0.9.0 新增）

| 功能 | 触发 | 输入 → 输出 | 状态 |
|---|---|---|---|
| **纯数字/信号词识别** | 自动（确定性分类，零调用） | `42` / `继续` / `ok` → 信号分支 | ✅ 单测 |
| **助手尾部锚点提取** | 信号输入时读会话 | surface → 最近一条助手话轮（选项/待答问题/待续提议所在） | ✅ 单测 |
| **选项选择推断** | 数字命中选项标记 | `1` + 「要不要继续？1. 梳理 2. 先停」→ 展开选中项 | ✅ 单测（含真实模型线上验证） |
| **数字作答推断** | 助手停在待答问题 | `15` + 「几号发布？」→ 数字即答案 | ✅ 单测 |
| **催答/继续推断** | 信号词 + 助手提议或用户未答问题 | `继续` → 放行提议的动作 | ✅ 单测 |
| **无法推断即明说** | 锚点对不上 / 无上下文 | `42` 对不上选项 → `cannot_infer`，**零模型调用** | ✅ 单测；模型回执 `[无法推断]`、输出未锚定同样转此码 |
| **短指令识别** | 自动 | `改一下` / `不对` / `换一个`（≤6 字、有动词、无锚定符） | ✅ 单测 |
| **度契约展开** | 短指令 + 上下文 | 指代从上下文消解；发散仅限动词自然子部件与隐含后续；禁新目标/技术栈/数值/范围 | ✅ 单测（含真实模型线上验证） |
| **动词逐字守恒** | 写回前 | 输出必须包含输入的实义字，`改` 不得变 `调整` | ✅ 单测 |
| **180 字硬上限** | 写回前 | 超限 → 一次收紧重试（带失败诊断后缀）→ 仍超限 `fidelity_rejected` | ✅ 单测（真实 >180 字越界样例） |
| **指代消解失败明说** | 模型回执 | `[无法确定指代对象]` → `cannot_infer` | ✅ 单测 |
| **mode 字段** | 事件日志 | `signal` / `deictic` 与 precise/elaborate 区分 | ✅ 单测 |

**设计边界（有意为之）**：推断锚点只认最近助手话轮与最近用户话轮；更早的未决项不回溯——
"信号指代上上文"的歧义度已经超过一个 300 字符锚点能承载的范围，宁可说无法推断。

## 验证覆盖说明

- **线上实测**（19 项）：走真实路由 + 真实模型，覆盖闸门、三类输入、深度、反馈、日志
- **脚本化 harness**（14 项）：用可编程 llm 桩驱动**线上无法按需触发**的路径（拒绝、修复、fail-open、路由安全、配置项、上下文按需）
- **单元测试**（104 项）：确定性逻辑、模板内容、客户端产物与渲染
- **无法验证**：浏览器内的真实点击（次级按钮）、视觉呈现、客户端 bundle 的实际下发（`/plugins` 路由需会话鉴权，外部访问 404）
